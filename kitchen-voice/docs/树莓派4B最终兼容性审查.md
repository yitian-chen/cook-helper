## 结论

**可以发给组员在树莓派4B上安装和调试。** 语音模块的代码结构、网络接口和Python依赖具备在64位Raspberry Pi OS桌面版上运行的条件。它不是Windows专用程序；Windows专用内容只剩按系统分别显示的操作提示。

## 为什么树莓派4B能承担语音模块

识别和合成由阿里云/讯飞云端完成。树莓派负责采集PCM音频、WAV读写、有限的重采样、HTTP服务和本地播放，不在本机运行大型语音模型。语音模块本身的计算量适合树莓派4B。

完整产品同时运行本地视频、浏览器、摄像头手势识别时，CPU、内存、散热和USB/蓝牙并发负载会增加。这个风险属于整机集成，不能由语音模块的单独测试消除。建议手势摄像头先用较低分辨率/帧率，并在最后阶段记录CPU温度、内存和卡顿。

## 推荐目标环境

- 树莓派4B，官方电源与正常散热。
- 当前官方64位Raspberry Pi OS桌面版，使用系统自带Python 3（支持说明范围3.11～3.13）。
- 在项目目录创建`.venv`，不复制Windows虚拟环境，不用sudo运行语音服务。
- 系统安装`python3-full`、`python3-venv`、`libportaudio2`、`libsndfile1`。
- C270i通过USB输入；蓝牙音箱先在系统中连接并设为输出，再启动程序。
- 首轮使用树莓派自己的浏览器访问`http://127.0.0.1:8765/`。

不推荐首次使用32位系统或无桌面音频环境的Lite镜像。理论上可以另行配置，但会增加Python二进制包和PipeWire/蓝牙音频的安装工作，不符合当前项目时间限制。

## 仍须目标机器验收的四个关口

1. `pip install -r requirements.txt`在目标网络和系统上完成。
2. 页面能列出C270i或系统默认输入，录音回放清晰。
3. 系统默认/可用Linux音频入口能把声音送到蓝牙音箱，断开重连后可恢复。
4. ASR、Agent、TTS连续三轮完成；之后再与本地视频和手势并行测试。

上述任一失败都应先定位安装、输入、输出、云端或整机负载中的具体环节，不直接推断树莓派4B性能不足。

## 实体按钮状态

当前语音服务已提供`/record/start`、`/record/stop`、`/pipeline`，网页可模拟整个按钮行为。GPIO驱动尚未包含。可以先开发配置化框架；硬件同学确认BCM编号、物理针脚、有效电平、3.3V安全性和消抖后再实测，不需要改ASR/TTS。
