# 讯飞版本：配置与分步测试

状态：交付版本20261121-team-voice-v3，讯飞接入完成，最近一次44项本地自动测试通过，用户反馈当前使用正常。模型准确率、延迟和树莓派音频实机表现仍需逐项测试。本文件讲云端配置；树莓派硬件安装与实体按钮安排见《树莓派联合调试指南》。

## 1. 这次接的是哪两个服务

| 环节 | 讯飞服务 | 本程序适配 |
|---|---|---|
| ASR：声音转文字 | 语音听写（流式版），`wss://iat-api.xfyun.cn/v2/iat` | 录完音再上传，普通话，16kHz 单声道 PCM16，处理动态修正 |
| TTS：文字转声音 | 在线语音合成，`wss://tts-api.xfyun.cn/v2/tts` | 默认发音人参数 `xiaoyan`；返回 PCM，本地保存 WAV / 流式播放 |

这两个接口不是星火 Agent、超拟人语音合成或“语音识别大模型”的通用接口。请在讯飞开放平台应用中开通对应的**语音听写（流式版）**和**在线语音合成**。本项目 Agent 仍使用原来的 mock/http 接口，不会因为更换语音服务自动变成讯飞星火。

官方依据：[语音听写接口](https://www.xfyun.cn/doc/asr/voicedictation/API.html)、[在线语音合成接口](https://www.xfyun.cn/doc/tts/online_tts/API.html)。音色是否可用，以你应用的在线合成控制台实际列出的发音人参数和权限为准。若没有 `xiaoyan`，使用该服务控制台给出的参数值，例如对应账号可用的 `x4_xiaoyan`；不要仅凭中文音色名称填写。

## 2. 现有项目不用重建

先停止原来运行服务的窗口：按 Ctrl+C。进入 `kitchen-voice` 目录，使用原虚拟环境更新依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
notepad .env
```

**已有 `.env` 不要用模板覆盖。** 在该文件中添加或修改以下行；同名项只保留一行。示例右侧是占位说明，必须换成真实值。密钥在讯飞应用的对应服务控制台查看，不发到聊天或 GitHub。

```ini
ASR_PROVIDER=xfyun
TTS_PROVIDER=xfyun
XFYUN_APP_ID=填写讯飞应用的APPID
XFYUN_API_KEY=填写对应APIKey
XFYUN_API_SECRET=填写对应APISecret
XFYUN_TTS_VOICE=xiaoyan
XFYUN_TTS_SPEED=50
XFYUN_TTS_VOLUME=50
XFYUN_TTS_PITCH=50
```

原有 `DASHSCOPE_*`、`ASR_MODEL`、`TTS_MODEL`、`TTS_VOICE` 保留；这些是阿里云参数，讯飞模式不使用它们。讯飞配置需要三个值，不能只把阿里云 API Key 换成讯飞 API Key。

如果 ASR 和 TTS 控制台显示的凭据不一样，可分别填写（非空的专用项优先于共用项）：

```ini
XFYUN_ASR_APP_ID=
XFYUN_ASR_API_KEY=
XFYUN_ASR_API_SECRET=
XFYUN_TTS_APP_ID=
XFYUN_TTS_API_KEY=
XFYUN_TTS_API_SECRET=
```

保存后，先检查配置名称和状态（不联网，也不打印密钥）：

```powershell
.\.venv\Scripts\python.exe -m voice providers
```

两个环节应显示 `provider: xfyun`、`configured: true`、`missing: []`。这只检查配置是否填写，不证明内容正确或权限已开通。

启动：

```powershell
.\.venv\Scripts\python.exe -m voice serve
```

打开 [本机测试页面](http://127.0.0.1:8765/)。如看到旧页面，按 Ctrl+F5 刷新。若修改 `.env` 后状态没变，确认先停止旧服务，再从同一项目目录启动；操作系统中已有同名环境变量会优先于 `.env`。

## 3. 页面怎么切换

顶部“云端服务选择”提供两个独立下拉框：识别可以用讯飞、播报可以用阿里云，也可以两者都选讯飞。点击**应用服务商选择**才生效。仅改变下拉框不生效。

页面切换会停止当前放音，不改麦克风/音箱选择；录音或云端请求进行中不允许切换。页面设置仅本次运行有效；长期默认由 `.env` 的 `ASR_PROVIDER` / `TTS_PROVIDER` 决定。保留两家凭据即可随时切回阿里云，失败时不会自动改用另一家收费服务。

## 4. 按顺序测试，每次只定位一个环节

| 顺序 | 操作 | 正确表现 | 能证明什么 |
|---|---|---|---|
| 1 本地输出 | 选音箱、应用，播放提示音 | 从实际所选设备出声 | 本地输出链路；不请求任何云端 |
| 2 本地录音 | 录“我想做番茄炒鸡蛋，做三人份”，结束并回放 | 声音清楚完整 | 麦克风采集；不代表识别成功 |
| 3 仅讯飞 ASR | 确认识别为讯飞，点击“把刚才的录音识别成文字” | 出现对应文字，核对菜名和数字 | 讯飞账号、网络、ASR权限与格式；此步联网、可能计费 |
| 4 仅讯飞 TTS 整段 | 确认播报为讯飞，填“已找到番茄炒鸡蛋的教程”，先取消“边生成边播放”再生成 | 合成完成后从所选音箱说出原文 | 讯飞TTS权限、音色、WAV保存及回放；不调用Agent |
| 5 讯飞 TTS 流式 | 换成另一句短文字，勾选“边生成边播放”后生成 | 收到音频后开始播放，页面显示首包等待时间 | 流式传输与设备采样率适配；首次测试不要用长教程 |
| 6 中断与缓存 | 播报时停止；另完成一条后再次生成相同文字 | 中断可结束；完整音频下次可命中缓存 | 未完成音频不缓存；缓存按服务商、音色、语速等隔离 |
| 7 完整流程 | 使用刚才录音，运行完整语音流程 | 显示识别文字、Agent回复并播报 | ASR→Agent→TTS整条交接；mock仍不控制视频 |
| 8 对照切换 | 切回阿里云或混用两家，重复短句 | 页面服务商状态正确，输出链路正确 | 可切换性；不同服务商不会共用错误音色缓存 |

同一条完整合成的语音可能命中缓存，因此比较两家延迟时记录 `cache_hit`，首次测试使用不同文字或在停服后删除指定 `runtime/tts-cache-*.wav` 文件。缓存命中没有云端合成等待，不能据此比较模型速度。`首次提交音频播放` 是近似等待，不含蓝牙音箱缓冲及实际可听到的延迟。

当前仍是“录音结束再识别”，不是实时边说边显示文字。讯飞听写按音频时长节奏上传，**录了10秒，识别阶段可能还要花接近10秒上传，再加连接和服务端处理**；不要把这段时间当作 Agent 速度。先录3～5秒短句验证正确性。默认录音上限20秒、云端/流式总超时45秒；长文本播报可能触发总超时，先用短句，确需延长时修改 `CLOUD_TIMEOUT_SECONDS`（本程序允许1～180秒）并重启。讯飞听写单条仍限60秒，TTS文字须少于8000个UTF-8字节；本程序另限2000字符。

流式音频使用讯飞支持的16kHz（必要时8kHz），再适配音箱。设备只接受48kHz或44.1kHz时使用有状态插值升采样，不把音箱采样率直接传给讯飞；整段回放使用原有重采样。如果某个特殊设备要求降采样，流式模式会在调用前提示，可先改用整段合成。

## 5. 不想点页面时的测试入口

命令在项目目录执行；下列 WAV 路径换成你录到的真实文件。除了配置检查，ASR / TTS 会联网、可能计费。

```powershell
.\.venv\Scripts\python.exe -m voice providers
.\.venv\Scripts\python.exe -m voice record --seconds 4
.\.venv\Scripts\python.exe -m voice asr "runtime/这里换成录音文件名.wav"
.\.venv\Scripts\python.exe -m voice tts "已找到番茄炒鸡蛋的教程"
.\.venv\Scripts\python.exe -m voice play "runtime/这里换成生成文件名.wav"
```

现有 `/record/start`、`/record/stop`、`/asr`、`/tts`、`/tts/speak`、`/play`、`/play/stop`、`/pipeline` 接口保留。新增：

| 测试入口 | 含义 |
|---|---|
| `GET /providers` | 只显示两环节当前服务商、模型、配置是否填写、缺失字段名称；不联网、不返回密钥 |
| `POST /settings/providers` | JSON：`{"asr_provider":"xfyun","tts_provider":"xfyun"}`，应用本次运行选择 |

## 6. 出错先看哪一类

- 提示音或回放失败：本地设备问题，与讯飞密钥无关。连接蓝牙后重新扫描，重新选择并应用。Windows 优先使用明确的 WASAPI / DirectSound 设备；系统默认会跟随系统路由。
- 缺少配置：按页面列出的名称填写，重启服务。ASR和TTS单独检查，不需要为测试一个环节先配置另一个。
- 讯飞连接失败：核对三项凭据、服务开通状态、网络和电脑时间；签名鉴权需要正确系统时间。代码保留TLS证书校验，不通过关闭校验来解决连接问题。
- 讯飞错误码：页面显示数值错误码，按上述官方文档查；音色需要该应用有权限。程序不显示服务端原始诊断和带签名的连接地址。
- 流式失败或断网：可以停止播报，未完整结束的数据不存为缓存。已经发起的请求可能消耗额度，不自动重试。
- 完整流程会回显而不执行视频：`AGENT_MODE=mock` 是占位测试；只有切到同学提供的真实HTTP Agent后才能测试系统动作。
