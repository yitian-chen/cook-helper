# 已有经验与本轮约定

## 项目边界

三人合作，树莓派4B作为目标设备。语音模块负责本地录音、云端ASR、把识别全文交给Agent、云端TTS、本地放音。菜谱库、视频播放和手势由主系统接入。所有语音文字仍交给Agent，不增加固定指令捷径；更换ASR/TTS不会替换Agent。

## 已经确认的经验

1. **先测本地，再测云端。** 提示音和录音回放不需要密钥；录音成功不等于识别成功。云端识别、Agent处理、云端合成和播放应保留独立入口。
2. **设备列表必须来自运行Python服务的那台机器。** 电脑可用内置麦克风；树莓派计划用罗技摄像头自带USB麦克风和蓝牙音箱。电脑设备编号不能复制到树莓派。
3. **配对、连接、被系统识别为可用播放设备是不同状态。** 蓝牙热插拔后只重读旧设备列表不可靠，要真正重新扫描；扫描后清空旧编号，重新应用选择。
4. **设备名称不保证物理路由。** 本机MME的旧Realtek标签曾在蓝牙连接后输出到蓝牙；明确选择WASAPI/DirectSound并试听，才确认真实出声位置。系统默认会跟随系统设置。
5. **音频库调用线程必须一致。** FastAPI请求线程中直接创建和操作PortAudio曾出现本地脚本成功、网页失败的情况。现在统一交给 `audio_runtime.py` 的专用线程；保留此修复，不为接新模型重写设备层。
6. **选定设备失败就报错，不悄悄切默认设备。** 回放展示实际打开的设备编号、名称和接口；不让错误路由被“能听见声音”掩盖。
7. **云端格式与设备格式分开。** 麦克风按可用采样率录制，再转换为识别要求的16kHz单声道PCM16。讯飞合成16kHz，不代表音箱必须直接接受16kHz；通过本地适配播放。
8. **延迟要分段测。** ASR、Agent、TTS和蓝牙缓冲分别耗时；流式可缩短首次出声等待，缓存可避免重复合成，但不等于云模型更快。长播报还有播放本身的时间与总超时限制。
9. **错误不能全部归因于云端。** `PortAudioError`、驱动错误与密钥无关；配置已填写不等于权限与额度可用。平台错误只显示安全说明和数值错误码，不回显签名地址或原始SDK日志。
10. **只保留当前源码。** 历史蓝牙版、回退前源码和重复交付包已经删除；当前唯一源码目录为`kitchen-voice`，唯一对外版本为`20261121-team-voice-v3`。测试录音和语音缓存不是源码版本，保留在被Git忽略的`runtime`中供本机复测。

## 本轮实现约定

- 默认兼容原阿里云配置；ASR和TTS分别选择 `aliyun` / `xfyun`，不跨平台套用密钥。
- 不覆盖已有 `.env`。模板只列变量名称；GitHub和源码压缩包不包含密钥、录音、缓存或虚拟环境。
- 页面切换仅本次运行有效，持久默认写 `.env` 后重启；忙时拒绝切换。
- 讯飞ASR按片段序号处理追加与替换，避免把“识别中的文字”重复拼成错误指令。未收到完整结束结果不当作成功。
- TTS只有完整结束的PCM才保存缓存；缓存标识包含服务商、音色、语速等，防止混用旧音频。
- 子进程提供硬超时和取消；不因失败自动重试可能计费的调用，也不自动重试Agent命令。
- `AGENT_MODE=mock` 明确显示为模拟，不宣称视频控制已完成；真实Agent仍需提供请求编号和 `reply_text`。
- 组员交付版已重写树莓派硬件调试说明，加入双服务商、配置交接和网页先验收/按钮并行开发流程；树莓派实机结果仍需填写人工验收记录，不预填通过。
