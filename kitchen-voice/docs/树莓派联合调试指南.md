# 智能厨房助手：树莓派硬件调试说明

交付版本：`20261121-team-voice-v3`。适用硬件：树莓派4B、C270i自带USB麦克风、蓝牙音箱、显示屏。语音识别与合成支持分别选择讯飞或阿里云。

**第一天目标：在树莓派上用网页录一句话，让所选音箱播报回复。先不接实体按钮、视频或手势。**

## 1. 现状和分工

| 人员 | 首轮任务 | 回传内容 |
|---|---|---|
| 语音开发同学 | 提供源码、私密配置、语音接口，处理ASR/TTS问题 | 版本和配置说明 |
| 硬件/树莓派同学 | Linux安装、设备连接、网页测试、确认按钮接口 | 系统信息、设备名称、测试结果、按钮信息表 |
| Agent/主系统同学 | HTTP Agent、菜谱库、本地播放器、手势协调 | 可访问接口和符合协议的响应 |

最近一次44项离线自动测试通过，当前电脑设备扫描与按选择输出已由用户确认，用户反馈当前使用正常；ARM64/Python 3.13全部Python依赖已解析下载成功。它们不能代替树莓派实机验收。GPIO驱动与视频/手势整机协调不在本语音模块中；默认Agent为mock，不控制视频。

**不用等按钮装好才开发。** 硬件同学现在用网页验证语音模块；语音同学可同时写按下/松开的可配置适配框架，预留GPIO编号、有效电平和消抖参数。接线信息确认后配置并实测，不需要重写ASR/TTS。

## 2. 两个包怎么放

解压源码包得到`kitchen-voice`；单独解压私密配置包，把里面的`.env`复制到`kitchen-voice`内部，与`README.md`和`requirements.txt`同级。

```text
源码解压位置/
└─ kitchen-voice/
   ├─ .env                ← 私密包里的文件放这里
   ├─ .env.example        ← 空白模板可保留
   ├─ README.md
   ├─ requirements.txt
   ├─ voice/
   ├─ docs/
   └─ tests/
```

不用把内容粘进Python，不能改名为`.env.txt`。Linux中点开头文件可能隐藏，按Ctrl+H或执行`ls -a`查看。已有自己的`.env`时先备份，再决定合并。

私密包含真实密钥，使用会消耗对应账号额度，只通过私下渠道发给获授权组员，不上传GitHub。普通源码包不含真实密钥。配置副本已清空Windows设备编号；原开发机`.env`未变。

不要复制Windows的虚拟环境、`.deps`、录音和缓存。源码包内`交付清单.json`用于双方确认版本。不要用旧版源码覆盖本版。

## 3. 硬件连接与系统准备

| 设备 | 首轮做法 | 检查 |
|---|---|---|
| 树莓派4B | 使用现有官方USB-C电源 | 正常开机、联网和散热 |
| 显示屏 | 按已购屏的实际接口接线；HDMI屏接树莓派Micro-HDMI，触摸通常另接USB | 供电遵照屏幕标注，显示/触摸正常 |
| C270i | 接USB | 系统能识别其音频输入；摄像头不占HDMI口 |
| 蓝牙音箱 | 在系统中配对、连接并设为声音输出 | 先用系统声音确认实际出声 |
| 实体按钮 | 首轮不接入语音操作 | 后面确认电平、引脚和事件逻辑 |

LM2596不是首轮语音测试必需部件。额外电源先不接树莓派GPIO供电；后续若给附件供电，先按附件额定电压调节并测量，再接负载。不要把12V适配器或5V信号接GPIO信号脚。

树莓派GPIO为3.3V逻辑，不耐5V；BCM编号与物理针脚号不同。[树莓派官方硬件说明](https://www.raspberrypi.com/documentation/computers/raspberry-pi.html)。

建议64位Raspberry Pi OS桌面环境和系统自带Python 3.11～3.13。最新64位系统的ARM64/Python 3.13依赖已在交付前完成下载解析验证；这证明依赖有兼容包，音频设备仍需实机测试。先记录：

```bash
cat /etc/os-release
uname -m
python3 --version
```

若不是`aarch64`，记录实际架构，依赖安装需单独验证。蓝牙配对不等于音频已连接。用当前桌面用户运行Python，不用sudo启动服务，以免切换音频会话。

## 4. 安装，只做一次

终端进入`kitchen-voice`目录，用`pwd`和`ls -a`确认看得到`voice`、`.env`和`requirements.txt`。

```bash
sudo apt update
sudo apt install python3-full python3-venv libportaudio2 libsndfile1
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
```

安装失败先保留错误末尾，不继续启动，也不使用`sudo pip install`绕过问题。已接收团队配置的同学无需重新创建`.env`；使用自己账号时才执行：

```bash
[ -f .env ] || cp .env.example .env
nano .env
```

`nano`保存用Ctrl+O、回车，退出用Ctrl+X；不把配置内容截图发到群里。

## 5. 检查配置与启动

```bash
.venv/bin/python -m voice providers
```

应显示所选服务商和`configured: true`、`missing: []`。只检查是否填写，不证明权限、额度和音色可用。

| 配置 | 意义 |
|---|---|
| `ASR_PROVIDER` / `TTS_PROVIDER` | 各自选`xfyun`或`aliyun`，可以混用 |
| `XFYUN_APP_ID/API_KEY/API_SECRET` | 讯飞共用凭据；非空`XFYUN_ASR_*` / `XFYUN_TTS_*`优先 |
| `DASHSCOPE_API_KEY/WORKSPACE/REGION` | 阿里云密钥、业务空间与地域 |
| `INPUT_DEVICE` / `OUTPUT_DEVICE` | 首次留空，在目标机器页面重新选择 |
| `AGENT_MODE` | 首轮保持`mock` |
| `MAX_RECORD_SECONDS` | 默认录音上限20秒，首次只录3～5秒 |
| `CLOUD_TIMEOUT_SECONDS` | 默认45秒总超时，先播报短文字 |

若团队配置已切真实Agent但该服务尚未可达，先改`AGENT_MODE=mock`。修改配置后需重启才加载。

启动：

```bash
.venv/bin/python -m voice serve
```

看到`Uvicorn running on http://127.0.0.1:8765`，保留终端运行，在**树莓派自己的浏览器**打开：

```text
http://127.0.0.1:8765/
```

网址必须带`:8765`。服务运行时终端持续等待；若又出现输入提示符，说明已退出，查看上方报错。Ctrl+C停止，重新执行启动命令即为重启；关闭网页不会停止服务。

电脑的127.0.0.1指电脑自己。若从电脑操作，可用远程桌面打开树莓派浏览器；或在已开启SSH的条件下，从电脑建立转发：

```bash
ssh -L 8766:127.0.0.1:8765 用户名@树莓派实际IP
```

保持SSH连接，电脑访问`http://127.0.0.1:8766/`，仍使用树莓派麦克风和音箱。用户名和IP替换为实际值。当前服务不直接开放局域网监听，不用多个worker运行音频服务。

## 6. 首轮逐项验收

| 顺序 | 操作 | 通过标准 |
|---|---|---|
| 1 | 重新扫描，选择C270i输入和目标音箱，应用 | 实物与选项相符，应用成功 |
| 2 | 播放提示音 | 从实际选择的音箱出声 |
| 3 | 录“我想做番茄炒鸡蛋，做三人份”，结束回放 | 清楚完整，无明显截断 |
| 4 | 识别录音 | 核对菜名与人数，记录服务商和耗时 |
| 5 | 输入短句“已找到番茄炒鸡蛋的教程”，取消边生成边播放后生成 | 整段合成、出声正确 |
| 6 | 换句短文字，开启边生成边播放，测试停止 | 正常播报，停止有效，无明显变调/断续 |
| 7 | 完成一条后再次生成相同文字 | 可命中缓存；缓存耗时不用于比较模型速度 |
| 8 | 切换另一服务商后重复ASR/TTS | 当前状态一致，分别验证权限和额度 |
| 9 | 完整流程 | 识别→mock Agent→播报串通；mock不控制视频 |
| 10 | 连续三轮 | 无卡死、设备占用或旧录音重复提交 |

Linux可能只显示`default`、`pulse`等入口，不显示蓝牙品牌；先在系统声音设置选目标音箱，再测默认输出。不需要出现Windows的MME/WASAPI。

蓝牙连接/断开后重新扫描会停止放音并清除旧选择，要重新选择并应用。录音和处理时不扫描，不同时运行网页与CLI录音。

本地录音回放不联网，ASR/TTS会用云端额度。讯飞当前录完再按音频时长节奏上传，录3～5秒还可能花接近对应时长上传，再加连接和处理；这部分不是Agent延迟。

## 7. 声音调整与故障定位

讯飞在`.env`中修改`XFYUN_TTS_VOICE`为控制台已开通发音人参数；`XFYUN_TTS_SPEED`、`XFYUN_TTS_PITCH`、`XFYUN_TTS_VOLUME`为语速、音高、音量，默认50、范围0～100。修改后重启并重新生成，“再次播放”还是旧音频。若整段正常、只有流式变调/杂音，先检查播放链路。

| 现象 | 首先处理 |
|---|---|
| `No module named ...` | 用`.venv/bin/python`安装requirements；`dotenv`对应依赖名`python-dotenv` |
| 网页连接被拒绝 | 看终端是否仍运行，网址是否带8765，是否在正确机器访问 |
| 端口占用 | 到旧服务窗口Ctrl+C；Linux可用`ss -ltnp 'sport = :8765'`定位，不误杀其他程序 |
| 提示音也失败 | 先查系统声音、设备连接、默认音箱，与密钥无关 |
| 云端按钮禁用 | 检查`voice providers`列出的缺少字段，修改后重启 |
| 讯飞连接失败/错误码 | 查对应服务凭据、权限、额度、音色、系统时间和网络；保留TLS校验 |
| 长文本流式超时 | 总时限默认45秒含播放，先用短句；参数允许1～180秒 |
| 完整流程不控制视频 | mock占位正常，真实Agent接入后再测 |

## 8. 实体按钮：可并行开发，接线确认后实测

当前没有GPIO驱动，但可以先写配置化框架，用网页/HTTP模拟输入，不必等按钮全部装好。硬件同学需先确认以下信息，再进行正式接线和GPIO测试。

| 信息 | 硬件同学填写 |
|---|---|
| 按钮型号、说明或原理图 | |
| 裸机械按钮，还是VCC/GND/OUT模块 | |
| 是否自复位，按住是否稳定保持 | |
| 供电电压、OUT最高实际电压 | |
| 按下与松开分别高/低电平 | |
| 是否带上拉/下拉，是否共地 | |
| BCM GPIO编号 | |
| 对应物理针脚号 | |
| 指示灯接口和驱动方式（如有） | |
| 其他模块已占用的GPIO | |
| 接线照片 | |

正式交互为**按住录音、松开提交**。GPIO程序只发送事件，不另起一套录音器。断电接线，信号最高3.3V；5V信号须先合适转换电平。

| 事件 | 本机请求 | 约束 |
|---|---|---|
| 按下 | `POST /record/start`，JSON `{}` | 成功才标记本轮开始 |
| 松开 | `POST /record/stop`，JSON `{}` | 取返回的`file` |
| 结束成功 | `POST /pipeline`，JSON `{"file":"刚返回的文件名.wav","play":true}` | 每轮只提交一次 |

地址为树莓派`http://127.0.0.1:8765`。GPIO回调做消抖，把HTTP操作放串行队列，不阻塞回调。快速松手也要先完成start再stop；start被忙状态拒绝时，不得提交旧录音。超过录音上限自动结束后，松开可取文件，仍只提交一次。

`/play/stop`只停止播报，不取消已发出的ASR/Agent请求。处理中暂不开新录音，不自动重试pipeline以免动作重复。

## 9. 最后接真实Agent、视频与手势

先由同学提供真实POST地址，再设置`AGENT_MODE=http`、`AGENT_URL`、可选`AGENT_TOKEN`。Agent在其他电脑上时，URL写那台电脑的实际可达IP，不能写树莓派的127.0.0.1。

请求`{"request_id":"唯一编号","text":"识别原文"}`；响应`{"request_id":"同一编号","reply_text":"可朗读回复"}`。先单测`POST /agent`再测pipeline；Agent取得动作结果后再确认成功。

主系统负责录音前暂停/静音视频、临时阻止手势误操作，结束后结合原状态与Agent结果决定恢复。语音模块只停止自己的播报，不会自动暂停教学视频。手势接入后查设备争用；语音模块只打开C270i音频输入，不打开视频采集。
